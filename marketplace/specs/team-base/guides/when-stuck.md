# 遇到问题时

## 先自己排查（最多 30 分钟到半天）

1. 复现问题，记录准确的错误信息。
2. 阅读相关代码、日志和最近的改动。
3. 一次只验证一个假设。
4. 使用 `team-systematic-debugging` Skill。

## 该停下来的情况

- 连续两次修复都没有成功。
- 问题来自需求不清楚，或者设计上有冲突。
- 需要修改其他人负责的模块、公共文件或高风险代码。
- 依赖的接口、资料或环境没有准备好。

## 怎么求助

在 Issue 或团队频道中写清：

```text
目标：要做什么
现象：准确的错误信息或截图
复现：步骤或测试
已尝试：做了什么，结果如何
当前判断：怀疑的原因
需要：需要谁做什么决定或提供什么
```

任务被阻塞时，把看板上的状态改为 Blocked，并写明在等谁。
