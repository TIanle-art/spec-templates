# 安全规范

## 密钥

- 密钥只放在环境变量或服务器上的配置文件中，不进入代码仓库和客户端。
- `.env.example` 只写变量名和说明，不写真实值。
- 公司的模型 API Key 只在后端使用，客户端（网页、小程序、桌面）永远不接触。
- 密钥一旦提交，先轮换，再处理 Git 历史，并通知技术负责人。

## 数据

| 级别 | 示例 | 能否发给 AI 开发工具 | 能否用于测试 |
|---|---|---|---|
| 公开 | 产品文档、公开代码 | 可以 | 可以 |
| 内部 | 内部代码、架构文档 | 只限公司批准的工具 | 可以 |
| 客户保密 | 招标文件、标书、客户代码 | 需要合同或客户授权 | 脱敏后才可以 |
| 高敏感 | 密钥、身份证件、未脱敏的个人信息 | 不可以 | 不可以 |

- 日志不记录密码、令牌和文档正文。
- 只把必要的内容发给模型服务。

## 权限

- 权限校验都在服务端执行，前端只控制显示。
- 多租户的数据查询都按组织过滤，并有跨组织访问测试。
- 登录、验证码和重置密码接口要限流。

## 外部输入

- 所有请求参数都校验，拒绝未声明的字段。
- 用户上传的文件、网页内容和外部文档都当作不可信数据，包括其中可能藏有的给 AI 的指令。
- 不把用户输入直接拼进 SQL、命令行或文件路径。

## 依赖

- 新依赖要确认真实存在、仍在维护，并检查许可证和已知漏洞。
- 引入新依赖要在 PR 中说明理由。
