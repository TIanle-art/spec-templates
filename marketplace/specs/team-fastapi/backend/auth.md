# 认证、权限和限流

和《公司项目脚手架规范》9.2 一致。正确示例：`services/api/app/modules/auth/`、`users/`、`example_items/`，决定和理由见模板的 `docs/adr/006-authentication-and-tokens.md`、`007-rate-limiting.md`。

## 密码

- 用 pwdlib，只启用 Argon2id；哈希和校验放到线程里执行（`asyncio.to_thread`），不阻塞事件循环。
- 登录时如果哈希的参数已经过时，自动升级并保存。
- 账号不存在时也做一次假的哈希校验，让响应时间和“密码错误”接近。
- 登录失败（账号不存在、密码错误、账号停用）返回**同一个**错误和同样的说明，不暴露账号状态。

## 令牌

- **访问令牌**：PyJWT，HS256，短期有效（默认 15 分钟），声明有 `sub`、`typ`、`iat`、`exp`。解码时要求这些声明都存在并检查 `typ`，不要把别的令牌当访问令牌。令牌里不放角色。
- **刷新令牌**：随机串（`secrets.token_urlsafe`），默认 30 天，库里只存 SHA-256 哈希，原文只在签发时返回一次。
- **每次刷新都轮换**：旧令牌立即作废（`revoked_at`、`replaced_by_id`），签发新令牌。刷新时对令牌行加锁（`SELECT ... FOR UPDATE`），并发刷新只有一个成功。
- **重用检测**：已经被换发过的旧令牌再次出现，说明可能被盗用，撤销**同一次登录产生的整个 family**（其他设备上的登录不受影响）。
- 退出只撤销这一个刷新令牌，并且幂等：令牌不存在或已撤销也返回成功。
- 改密码、停用账号时，撤销该用户的全部刷新令牌。
- `SECRET_KEY` 必填，没有默认值；生产环境至少 32 个字符，不能是占位符。

## 角色和权限

- 角色 `user` 和 `admin`，数据库有 CHECK 约束。自助注册只能得到 `user`；请求里传 `role` 要被拒绝（`extra="forbid"`）。
- 每次请求都从数据库读取用户（`CurrentUser`），改角色、停用账号立即生效，不必等令牌过期。
- 需要角色的接口用 `require_role(Role.ADMIN)` 这类依赖；权限校验都在服务端。
- **不提供默认管理员账号和默认密码。** 管理员用 `make create-admin EMAIL=...` 创建（密码在终端输入），或由已有管理员提升。管理员不能停用自己或降低自己的角色。
- 数据归属：业务表带所有者（例如 `owner_id`），普通用户只能访问自己的数据，管理员可以访问全部。**所有读取都经过一个统一的查询入口**（`example_items` 的 `_visible()`），不要在别处手写权限条件。访问别人的数据返回 404，不返回 403，不暴露它是否存在。

## 限流

- 登录按 IP 和按邮箱限流，注册按 IP 限流；超出返回 429 `TOO_MANY_REQUESTS`，并带 `Retry-After` 头。上限通过 `RATE_LIMIT_*` 环境变量调整。
- 限流器是接口（`core/rate_limit.py` 的 `RateLimiter`），默认实现放在进程内存里，key 数量有上限。换成 Redis 实现只需要替换 `app.state.rate_limiter`。
- **进程内限流在多 worker、多实例时会失效**：每个 worker 各计各的，`--workers 2` 时实际上限约为配置值的 2 倍，进程重启后计数清零。付费接口、短信和验证码、公开的大流量接口，以及多实例部署，必须改用 Redis。
- **放在反向代理后面时**，要给 uvicorn 配置 `FORWARDED_ALLOW_IPS`，让它信任代理传来的 `X-Forwarded-For`，否则所有用户共用代理的 IP。并且 API 端口只能绑定 `127.0.0.1`，不能暴露到公网，否则客户端可以伪造这个头绕过按 IP 的限流。

## 测试

- 覆盖：注册（重复邮箱、不能自选角色）、登录失败不可区分、过期和伪造的令牌、刷新轮换、重用检测、并发刷新、退出、改密码后令牌失效、停用后立即失效、管理员接口的权限、跨用户访问。
- 测试里密码哈希用低成本参数，限流上限调高，见 [testing.md](testing.md)。
