# 后端测试

- 使用 pytest，测试放在 `services/api/tests/`，按模块组织。
- 接口测试使用 FastAPI 的测试客户端，覆盖正常、错误、未登录、无权限和跨用户（组织）访问。
- **数据库：** 需要数据库的测试使用独立的 `<库名>_test` 数据库，由 `tests/conftest.py` 自动创建并迁移。库名不以 `_test` 结尾时拒绝运行，防止清空开发库或共享库。每个测试开始前清空表，测试之间的数据互不影响。
- **环境变量：** CI 只提供 `DATABASE_URL` 和 `APP_ENV=test` 两个变量。只有这两个变量时，全部测试也要通过：测试需要的其他配置（`SECRET_KEY`、限流上限等）在 `conftest.py` 里设置测试值。不能为了让测试通过而放宽生产环境的配置校验。
- 测试里的密码哈希换成最低成本的 Argon2 参数，只为加快测试；生产使用默认参数。
- 登录、注册的限流在 `conftest.py` 里调高；限流本身的测试在用例里单独设置低值。
- 外部服务（模型 API、微信、对象存储）在测试中使用模拟实现，不调用真实服务。AI 网关的测试用 `FakeProvider` 或脚本化的服务商，用 `httpx.MockTransport` 测 HTTP 层。
- 后台任务的测试覆盖成功、失败和重试，确认具有幂等性。
- AI 功能除了单元测试，还要运行 `evals/` 中的评估（`make eval`，对真实服务商运行，需要密钥，不进 CI）。
- 给关键测试做变异检查：故意改坏实现（让限额不触发、不记录取消等），测试应该失败。
